Privacidad English

Última actualización: 24 de noviembre de 2026

Resumen: no hay una SOQL ni una SOSL que devuelva de forma fiable todos los registros que creó o modificó un usuario. SOQL consulta un objeto cada vez; SOSL cruza objetos pero exige un término de búsqueda y se trunca a ~2.000 resultados. AuditLens consulta objeto a objeto y lo explica en pantalla.

Por qué no hay una consulta única

SOQL es mono-objeto. Permite relaciones y subconsultas dentro de un objeto, pero no UNION ni joins entre objetos. «Todo lo de este usuario» son N consultas, una por objeto.

SOSL sí cruza objetos y admite WHERE dentro de RETURNING, pero FIND es obligatorio: no existe un «buscar todo». El truco FIND '* OR *' aplica los filtros después del índice, así que con muchas filas devuelve vacío o incompleto sin avisar.

FIND {acme}
IN ALL FIELDS
RETURNING Account(Id, Name WHERE CreatedById = '005...' AND CreatedDate = LAST_N_DAYS:1),
          Contact(Id, Name WHERE CreatedById = '005...')

El problema de «modificado»

LastModifiedById solo dice quién hizo la última modificación. Si Ana edita el lunes y Luis el martes, buscar LastModifiedById = Ana el lunes no la encuentra. Para un historial real hacen falta Field History Tracking, feed tracking, CDC o auditoría externa.

La consulta que usa AuditLens

Hasta 8 objetos y 200 registros por lista, con la sesión ya abierta y sin backend:

SELECT Id, Name, CreatedDate FROM Account
WHERE CreatedById = '005...'
  AND CreatedDate >= 2026-11-24T00:00:00Z
  AND CreatedDate <= 2026-11-24T23:59:59Z
ORDER BY CreatedDate DESC
LIMIT 200

Y la misma con LastModifiedById / LastModifiedDate para los modificados. Los registros se muestran en pantalla, no se guardan, y la extensión es de solo lectura.

Límites que conviene conocer

  • FeedItem solo cubre campos con feed tracking (máximo 20 por objeto), no incluye creaciones y Salesforce borra los cambios de más de 45 días sin likes ni comentarios.
  • FieldHistoryArchive requiere Shield o Field Audit Trail, no se puede filtrar por usuario y tampoco incluye creaciones.
  • Change Data Capture sí trae creaciones, cambios y borrados con autor, pero solo conserva 3 días y se consume por streaming, no por SOQL.
  • Las consultas por objeto consumen límites de API y dependen de permisos y sharing: no hay forma de saltárselos desde el navegador.

AuditLens consulta hasta 8 objetos y 200 registros por lista, y lo dice en pantalla en lugar de prometer «todo».

Verificación

Conclusiones basadas en la documentación oficial de Salesforce y en casos publicados. No se han ejecutado contra una org real: la atribución de FeedItem.CreatedById, los límites por edición y el comportamiento de FieldHistoryArchive conviene comprobarlos en la org donde se use.

Technical notes

Last updated: November 24, 2026

Summary: no single SOQL or SOSL query reliably returns every record a user created or modified. SOQL is single-object; SOSL spans objects but requires a search term and truncates at ~2,000 results. AuditLens queries object by object and says so in the UI.

Why there is no single query

SOQL has no UNION or cross-object joins, so "everything this user did" means one query per object. SOSL does span objects and supports WHERE inside RETURNING, but FIND is mandatory and there is no match-all term; the FIND '* OR *' workaround filters after the search index and silently loses records past the ~2,000 cap.

"Modified by" is not a history

LastModifiedById only knows the latest editor. If Ana edits on Monday and Luis on Tuesday, a Monday search for Ana does not find it. Real history needs Field History Tracking, feed tracking, CDC or external auditing.

What AuditLens runs

Up to 8 objects and 200 rows per list, using the session already open, with no backend:

SELECT Id, Name, CreatedDate FROM Account
WHERE CreatedById = '005...'
  AND CreatedDate >= 2026-11-24T00:00:00Z
ORDER BY CreatedDate DESC
LIMIT 200

Plus the same query with LastModifiedById for modifications. Results are displayed on screen, never stored, and the extension is read-only.

Limits to keep in mind

  • FeedItem only covers feed-tracked fields (max 20 per object), never record creation, and Salesforce deletes tracked changes older than 45 days that have no likes or comments.
  • FieldHistoryArchive needs Shield or Field Audit Trail, cannot be filtered by user and does not include creations either.
  • Change Data Capture does include creates, updates and deletes with the author, but it is kept for 3 days and consumed by streaming, not SOQL.
  • Per-object queries consume API limits and depend on permissions and sharing; there is no browser-side way around that.

AuditLens queries up to 8 objects and 200 rows per list, and says so on screen instead of promising "everything".
